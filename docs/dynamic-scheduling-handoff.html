Dynamic Scheduling

Timezone-aware start and end times for campaigns, line items, and creatives, with a live Run State that says whether each one is actually serving. It replaces flipping statuses by hand when flights end or get extended.

Reviewed with product · feedback applied as of 2026-10-15 PRD WEB-1812 React · TypeScript · MUI localhost:5176 Builds on: Radius Ad-Tags
Read this first

A UX prototype, not a partial build

There's no backend: all state lives in the browser, and the clock can be simulated. Its job is to pin down the screens and behavior. Back-end engineering implements however it sees fit: storage, ad-server evaluation, HubSpot, reporting.

Vocabulary

Active / Inactive is the manual status switch, and the clock never changes it. Run State is computed, and its good value is Serving. Serving is the PRD's computed "Active", renamed so the two can't be confused.

Everything it entails

Feature inventory

Setting a schedule

  • One schedule editor for every level, with Timezone first.
  • Immediate / Indefinite live in the date dropdowns. Only a specific date needs a time.
  • Every IANA zone, US zones pinned. Daylight-saving gaps and repeats handled.
  • Editable from the details panel or any table's pencil.

Parent / child

  • Empty campaign dates mean Immediate → Indefinite.
  • Empty line-item or creative dates follow the parent live ("From campaign").
  • No cascading edits: a parent never rewrites a child's own dates.
  • A parent can stop a child, but never extend it.

Run State & warnings

  • Six computed states, each with a hover tooltip saying what and why.
  • Five warning rules (overlap, start, end, timezone, coverage). They never block a save.
  • "Stop delivery now?" before any save that stops something Serving.

Tables & creatives

  • One combined Schedule column in every table, before Run State.
  • Weights split only among Serving creatives and re-balance on their own.
  • Create campaign → line item → creatives, from scratch.

Prototype-only (for testing; gone in production)

  • Preset sample / Demo toggle, each with its own saved data, plus ↻ Restart demo. See Testing.
  • Demo clock to jump time and watch states change.
The schedule

Start, end, timezone, and what empty means

FieldChoicesIf left empty
StartImmediate, or a specific date + timeCampaign: Immediate.
Line item / creative: follows the parent's start.
EndIndefinite, or a specific date + timeCampaign: Indefinite.
Line item / creative: follows the parent's end.
TimezoneAny IANA zone (US pinned first)New York. It only matters for a specific date + time.
  • Immediate starts the moment it's saved, or when the item is set Active. It then reads Immediate · Started Sep 15, 2026, 9:30 AM EDT. That moment is fixed; switching to Immediate later moves the start to that later moment.
  • Indefinite never ends. Neither Immediate nor Indefinite needs a time.
  • A specific bound needs both a date and a time. The end is exclusive and must come after the start.
  • New items: a new campaign is Immediate → Indefinite in New York. New line items and creatives start fully following their parent.
  • Times always read in the item's own zone. Changing the computer's timezone never changes a value.
Dependencies

Parent and child schedules

Each level has its own schedule. A child's start or end that's left empty follows the parent live, bound by bound. Anything the user set on the child stays put when the parent changes.

CampaignOct 1, 2026 9:00 AM → Dec 31, 2026 11:59 PM · New York
Line itemOct 1, 2026 9:00 AM from campaign → Nov 30, 2026 11:59 PM Start follows the campaign; the end was set on the line item.
CreativeOct 1 → Nov 30 start & end from line itemFollows the line item, which follows the campaign for its start.
  • No cascading edits. Editing a campaign never changes a line item's own dates or timezone. Editing a line item never changes the campaign or its creatives' own dates.
  • A parent can stop a child, never extend it. A child serves only if every level above it is Active and in its window, and the child is in its own window too. An Immediate → Indefinite campaign doesn't revive a line item whose own end has passed.
  • Extending revives. Move an expired end into the future, or clear it so it follows a parent that's still running, and it serves again with no reactivation.

Warnings

Out-of-sync schedules

Warnings flag a schedule that won't serve the way it reads. They never block a save. Two severities: ▲ Warning and ● High. A bound the child follows always matches its parent, so it never triggers a warning.

RuleSeverityExample message
Never overlaps: the child's whole window falls outside the parent's● High"Never serves: its whole schedule falls outside the campaign's (Sep 15, 2026, 12:00 AM EDT → Dec 31, 2026, 11:59 PM EST)."
Starts before the parent starts▲ Warning"Starts Sep 1, 2026, 12:00 AM EDT, before the campaign starts (Sep 15, 2026, 12:00 AM EDT). It won't serve until then."
Ends after the parent ends, including Indefinite under a parent with an end▲ Warning"Runs indefinitely, but the campaign ends Dec 31, 2026, 11:59 PM EST. It stops serving then."
Different timezone from the parent, when a specific time is involved▲ Warning"Set to its own timezone, Los Angeles time (PDT); the campaign uses New York time (EDT). The line item starts Oct 8, 2026, 12:00 AM PDT (Oct 8, 2026, 3:00 AM EDT campaign time)."
Coverage: the line item is Serving, but none of its creatives are● High"The line item is Serving, but none of its 2 creatives are. Nothing is delivering."

Confirmations: these do ask first

Any save that would stop something currently Serving asks "Stop delivery now?" and lists everything it stops, including children that follow the changed dates. That covers date changes and setting a campaign or line item Inactive. Changes that only resume or extend delivery save without asking. Removing a creative also confirms.

Creatives

Weighting under scheduling

  • Weights split delivery only among creatives Serving right now. A creative that hasn't started or has ended shows "–".
  • One Serving creative gets 100%. With no typed weights the split is even. Typed weights are kept, and the others share the rest. Over 100% scales to fit, in whole percents that always total 100.
  • The split re-balances on its own as creatives start and end. A typed weight is kept while its creative isn't serving and applies again when it's back.
  • Laid out like production: Add Weighted Creatives (library search), trash to remove, row selection, pagination, reset and sort on the Weighting header.

Example: Hero (typed 60%) and Cutdown are Serving at 60 / 40. When the Cutdown ends on Oct 31, the Hero goes to 100%. When the Holiday creative starts on Nov 20, the split is 60 / 40, Hero and Holiday.

Demo clockJumps time by +1 hour, +1 day, +1 week, +30 days, −1 day, or −1 week. It turns amber while simulated; Back to real time resets it. It applies in both modes.Watch Pending Start → Serving → Schedule Expired, warnings change, and weights re-balance.
  • Each mode keeps its own data. Switching between Preset sample and Demo never loses work. Each picks up where you left off, including the page you were on.
  • Data lives in this browser only and survives reloads. Another browser or machine starts fresh, and testers don't see each other's changes.
  • The preset sample runs on real time. Its states depend on today's date, so on a later day some line items will have started or ended. Use the demo clock to show a specific moment.
  • To reset everything (both modes and the clock), run this in the browser console: localStorage.removeItem('radius.scheduling.v1'); location.reload()

For engineers: under the hood

  • All state is one JSON object in localStorage under radius.scheduling.v1. state.mode is sample or demo. The other mode's campaigns, line items, creatives, and current page sit in state.parkedWorkspace, and the toggle swaps them.
  • Restart replaces only the Demo workspace. Seeds live in src/state/seedScheduling.ts.
  • "Now" is the real time plus a saved clockOffsetMs, re-evaluated every 15 seconds, so the clock applies everywhere and survives reloads.
  • Jump to an exact moment (browser console, replace the date): const s = JSON.parse(localStorage.getItem('radius.scheduling.v1')); s.clockOffsetMs = Date.parse('2026-11-05T17:00:00Z') - Date.now(); localStorage.setItem('radius.scheduling.v1', JSON.stringify(s)); location.reload()

Scoping the real build

Prototype vs. production

Prototype-only

  • The demo clock and the Preset sample / Demo toggle (see Testing).
  • Data in the browser; a fixed creative library; one advertiser (Kerv).
  • Run State computed in the page from the current moment.

Engineering owns

  • Storing UTC timestamps + the IANA zone (PRD R4).
  • Ad-server evaluation per request (R8–R10); the prototype mirrors its order.
  • Stamping the Immediate start on save or activation.
  • HubSpot in both directions, reporting, and warehouse isolation.
